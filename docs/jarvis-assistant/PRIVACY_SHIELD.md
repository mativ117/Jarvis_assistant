# Jarvis Context — Privacy Shield (mandatory release gate)

Status: requirements only; not implemented. Zero exposure is the design goal, not a guarantee against a compromised OS, privileged malware or unknown vulnerabilities.

## Non-negotiable defaults
- Screen capture is off; prefer selected non-sensitive structured data over pixels. No full desktop/background capture in MVP. Allow only individually approved source/window and session. Unknown source, permission failure, detection uncertainty, protected screen or invalid state => deny/pause, discard frame and cancel queued work.
- Explicitly exclude password managers, login/SSO and MFA flows, banking/payment, identity documents, sensitive OS dialogs, private/incognito windows, confidential work and notification previews. Never access password fields, clipboard, keystrokes or accessibility content by default. OS signals and user selection are imperfect; if a platform cannot reliably exclude a source, that capture mode remains unavailable. Do not depend on a regex or vision classifier alone.
- A dedicated local least-privilege capture component checks source policy before capture when possible; raw frames that necessarily reach it are transient only, never forwarded to a model, memory, chat, agent, overlay peer, logs, crash reporting, disk, thumbnails, backups, analytics or remote access by default. For MVP only local analysis of approved minimized content; no raw screenshots or captured text sent to any cloud model, phone or connector, even when general cloud inference is enabled. The local filter itself must never send data.
- Any data derived from an untrusted frame (OCR, embeddings, summaries, image crops, metadata) inherits its sensitive classification until independently approved under a deterministic allowlist; discard uncertain results. Do not treat redaction as proof of anonymity. Only structured, non-sensitive cards are eligible for sharing to a separately authenticated device; locked-device notifications use generic text.
- Separate capture and processing from tool execution, storage and network; deny outbound network from capture worker, no administrative permissions, no arbitrary shell, no app injection. No tool actions initiated by screen text. No raw content in exceptions or diagnostics; do not promise perfect memory erasure, protect swap/dumps and avoid retaining frames. Do not expose listener on public networks.
- Visible capture status and one-step stop/pause; revoke sessions on window changes, lock/sleep, disconnect or timeout; flush pending work and prevent late results. User can disable all contextual assistance. Avoid capturing the assistant's own overlay. Where reliable OS capture exclusion or screen protection cannot be verified, do not provide a sensitive overlay or put confidential information in it.
- Authenticated encrypted local/private device access, least privilege, device revocation and no sensitive data in URLs. No automatic cross-device sync of captured content. No personal data in the public repository.

## Acceptance before enabling
Synthetic canaries (never real secrets) in password fields, fake bank/identity pages, MFA dialogs, screenshots/QR codes, clipboard, protected and unknown windows, mixed sensitive content, prompt injection, stale frames, session revocation and disconnects. Verify policy and OS exclusion, no raw/derived secret in model requests, memory, logs, crash reports, files, notifications, or network traffic; test malicious instructions, data extraction, late events and negative authorization. Inspect UI/screenshots/recording behavior on Windows and iOS separately. Test with packet capture and filesystem monitoring inside a disposable environment. Any leak, unknown protection state or missing required negative test blocks release. Document residual OS, hardware, shoulder-surfing and privileged malware risks. No capture feature may ship until these gates pass.

# Foundation 0.5 — host shell shutdown

The upstream Python shell wrapper accepted environment passthrough and dispatched to a Rust implementation using Command::output() without env_clear. Upstream tests explicitly skipped environment isolation and timeout checks. The fork intentionally disables the named host shell tool in Python and Rust, including direct native execution; its PyO3 wrapper now propagates denial. Keep tool registration for compatibility; no runtime override. This is a breaking change for upstream shell-based workflows, acceptable for a read-only MVP but requires a full integration review. Docker shell, code interpreter, Git/file tools, connectors, alternate agents, plugin paths and network egress are not covered by this patch. Default profile currently has capabilities disabled and empty allowed_dirs is unrestricted; separate gates remain necessary. No claim of whole-runtime isolation.

Regression tests replace positive Python host-shell tests with negative direct-entry tests, and add Rust denial test. Full Python/Rust tests, build, native binding, and runtime verification are pending; static verification only. No project code executed. Rollback by reverting this topic-branch commit; do not restore host shell for personal deployment without a separately approved isolation design. Privacy Shield requirements added independently; overlay not implemented.

# Foundation 0.6 — direct host file tools paused

Evidence: upstream Python file tools treated an empty allowed_dirs list as unrestricted; native Rust direct file tools relied on sensitive filename checks and lacked a per-call directory allowlist. Filenames cannot reliably identify private content. Both named file_read/file_write entry points now deny in Python and Rust before touching paths or native IO. PyO3 direct bindings propagate refusal. Constructor compatibility retained; existing positive tests for these named tools are replaced by denial tests (original tests remain in git history). This intentionally breaks raw file-based upstream workflows. A separately reviewed user-selected import/read-only workspace broker will be required before documents can be used. Other tools, memory, upload handlers, plugins, path-policy and network surfaces remain unaudited; no global file isolation claim. No runtime or full integration tests executed. Review other tests referencing these tools, build and native binding in isolation. Rollback by reverting this topic commit; do not enable arbitrary file access for personal deployment. Guardian is a deferred product concept, not operational protection.

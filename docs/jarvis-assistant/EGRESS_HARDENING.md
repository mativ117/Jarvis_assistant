# Foundation 0.7 — direct HTTP entry point shutdown

Upstream Python HTTP tool expanded environment variables in supplied headers, could send arbitrary methods/bodies, and could dispatch into the Rust tool. Native Rust used its own HTTP client; its protection is not authorization to transmit user data. This fork now denies the named http_request tool in Python and Rust before argument parsing or network access and propagates denial through the PyO3 direct binding. Tool registration remains for compatibility. Existing positive direct-HTTP tests are replaced by negative tests; original tests remain in history. No global network isolation claim: web_search (including keyless search), model engines including Ollama, connectors, telemetry, downloads and other paths still need separate review, plus OS-enforced egress controls. A future broker must use destination/operation allowlists, local-vs-external distinction, data minimization, approval, credential isolation, redirects/DNS validation, timeouts, bounded responses and sanitized metadata. Local device adapters are not exempt and must use narrowly scoped authorization. No network requests, project execution or full CI performed for this patch; static verification only. Full build, negative tests, alternate path inventory and packet-capture tests are release blockers. Rollback by reverting on topic branch; do not enable raw network access in personal deployments.
